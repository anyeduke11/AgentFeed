# AgentFeed 迭代路线图（2026 Q4 ~ 2027 Q1）

> 生成：2026-09-20，基于《WeKnora × AgentFeed 横纵分析报告》结论制定
> 性质：对 `docs/dual-consumer-exits-design.md`（APPROVED 2026-09-19）的**修订提案**
> Status: **PROPOSED** —— 与原计划存在两处顺序调整，需裁决后生效

## 0. 与已批准计划的两处偏离（先说冲突，不平均处理）

| # | 原计划（dual-consumer-exits） | 本路线图 | 理由 |
|---|---|---|---|
| 1 | 第二期主体 = getContext 注入 | **第二期主体 = 检索基建**，注入顺延至第三期 | 原计划 Premise 1 自称「出口 1 查询质量是地基」，但全部工程量给了语料 triage（蒸什么），检索本身（怎么查到）零工程项。报告批判六：注入时代检索不准 = 主动污染上下文，比不注入更糟 |
| 2 | ——（报告建议注入优先于日报） | **日报保留在第一期尾，不砍** | 日报已批准且工程量极小（复用 daily 轮转）；报告批判二恰好要求给「推式人消费」保留独立验证窗口。为排序纯洁性砍掉已批小项不划算，故不采纳报告的字面排序，采纳其原理（检索 > 注入 > 日报的投入权重） |

其余条目（args 埋点、triage 蒸馏、日报生成器、recordSession、淘汰条件）全部沿用原计划，不重述设计细节，只排期。

## 1. 总原则（从报告六批判 + 三条第一性原理导出）

1. **出口优先于入口**：门禁冻结加码，工程产能全部投向出口链
2. **地基优先于楼层**：检索基建先于注入——能力复利公式的「转化率」一项由检索质量决定
3. **度量对准命题**：调用计数 + 复利代理双轨并行，防 Goodhart 失真
4. **叙事与现实对齐**：对外表述校准为「热知识缓存 + 按需蒸馏」，不用「集体记忆」指导决策
5. **中立性是宪法**：本地、不绑厂商、单机可跑——任何功能不得以磨损三属性换便利
6. **单人产能**：每期只一条主线，搭车项必须工程量极小

## 2. 分期路线

### Phase 0 — 裁决护航期（2026-09-20 → 10-03，观察期内）

第一期既定事项照常推进（triage 蒸馏、日报生成器），本阶段只加三件不动主链路的小事：

| # | 事项 | 说明 | 工程量 |
|---|---|---|---|
| P0.1 | 度量双轨落地 | mcp_call_logs 上做会话聚类分析（时间窗 + 工具序列），产出「query → read_entry → get_source 链路完成率」。零 schema 改动，一个分析脚本 + 落 docs/ 记录 | 半天 |
| P0.2 | 检索 baseline | 从 mcp_call_logs.args 取真实 query（不足 10 条则手动构造至 20 条代表性 query），重放 search_knowledge，人工标注 Top-3 命中，落基线记录。这是 Phase 2 检索改造的对照组，**没有基线就没有验收数字** | 半天 |
| P0.3 | 叙事校准 | README 及 docs 中「集体记忆」类措辞改为「热知识缓存 + 按需蒸馏」 | 半小时 |

**裁决日（~10-03）**：≥20 次真实调用跨 ≥3 天，**且** P0.1 链路完成率可解读（有跟随消费迹象）→ 进 Phase 1；未达标 → 降级处置：MCP 留自用，四出口冻结，转最小维护模式。

### Phase 1 — 第一期收尾（10-04 → 10-17，~2 周，沿用原批准内容）

| # | 事项 | 验收 |
|---|---|---|
| 1.1 | 蒸馏 triage：top 领域精选 ~500 篇，预算上限 + 连续失败熔断 | 蒸馏成功率、摘要非空率达标 |
| 1.2 | 日报生成器：落盘（避开扫描根）+ 专用端点 + source=daily | 连续产出 7 天且 HTML 打开 ≥5 次；打开为 0 → 按原裁决重议投递渠道，不直接砍 |
| 1.3 | 时间窗参数搭车：search_knowledge 加 since/until（原第二期条目，工程小提前） | 支撑「这周 agent 干了啥」类问答抽查可用 |

### Phase 2 — 查得准：检索基建（10-18 → 11-14，~4 周）★本路线图核心插入

| # | 事项 | 设计要点 |
|---|---|---|
| 2.1 | 关键词路 | wiki_entries（标题+摘要+要点）建 SQLite FTS5 虚表，CJK 用 trigram tokenizer；幂等建表沿用迁移规范 |
| 2.2 | 分块向量路 | entry.md 按 heading 分块，parent-child 检索（命中 child 段落，返回 parent 词条）；复用 embed job 与 file_embeddings 表 |
| 2.3 | 融合与重排 | RRF 融合双路；静态先验用双轨评分（quality_score × 3 + rule_score）。**外部 rerank 服务只做可选开关，不做默认**——成本 + 中立性（服务商无关）双重考虑 |
| 2.4 | search_knowledge 升级 | 混合召回替换现有单路，**7 工具签名不变**，不破坏已挂载方 |

**验收**：P0.2 的 20 条 baseline query 重放，Top-3 命中率相对提升 ≥50%（基线跑出来后再定绝对值目标，不预设）；不达标 → 回炉分块粒度 / 融合参数，不进 Phase 3。

### Phase 3 — 注入：getContext（11-15 → 12-12，~4 周，原第二期主体）

| # | 事项 | 设计要点 |
|---|---|---|
| 3.1 | getContext(domain) MCP 工具 | 领域摘要（蒸馏完成时增量聚合）+ top 产物清单；**token 预算建议 ≤1500 且可配置**（回应原 Open Question） |
| 3.2 | 各项目 CLAUDE.md 开工指引 | 逐项目手动加一行，这是推广成本所在，预留真实工作量 |
| 3.3 | 注入效果度量 | 注入后 24h 内同领域 search/read_entry 跟随率 + 会话抽查引用证据（对齐 flywheel V1 成功标准） |

**验收**：≥2 个项目实际用了注入 + 注入内容被消费证据 ≥3 例。
**淘汰**：注入后零跟随消费 → 回炉检索质量或接受注入仅做导航索引。

### Phase 4 — 写回 + 复利闭环（12-13 → 2027-01-09，~4 周，原第三期）

| # | 事项 | 设计要点 |
|---|---|---|
| 4.1 | recordSession → session_notes 独立实验表 | 沿用原设计：不进 scan/gate 主链路，不污染语料 |
| 4.2 | **北极星指标上线** | 写回会话中注入/查询知识被引用率——最接近「能力复利」thesis 的可测代理，取代调用计数成为决策依据 |
| 4.3 | 日报渠道升级 | source=daily 打开达标 → macOS 本地通知（微信/邮件仍后置）；日报数据源接入 session_notes（原「集体日记」） |

**淘汰条件**（沿用原计划）：查询频次 <5 次/周 → recordSession 永久搁置。

### Phase 5 — 开源发布（2027-01 起，视 Phase 1~4 数据）

前置条件：Phase 0/3 验收达标（复利证据存在）+ flywheel P3 验证启动。

| # | 事项 | 说明 |
|---|---|---|
| 5.1 | 中立性宪法入 README | 「本地优先 / 不绑厂商 / 单机可跑」三属性 + 承诺条款：不以磨损三属性换便利（报告行动启示 5——应对上游挤压的唯三护城河） |
| 5.2 | 事实修正 | Express badge 改 4（非 5）、表数 20、views 8、Agent 目录 22——横纵报告诚实声明中列出的文档-代码差异 |
| 5.3 | 部署故事 | service.sh 的 lsof 依赖做平台抽象（macOS/Linux 双路径）或明确文档化仅 macOS——无 Linux 故事是开源分发的硬约束 |
| 5.4 | 发布试水 | 沿用原计划：npm 抽包或整仓 + HN/V2EX 单帖，验证 P3（下载量/issue） |

## 3. 贯穿红线（全文有效）

- 冻结维持：8 个 web view 仅维护、M1~M5 阅读闭环冻结、门禁不加码
- 蒸馏只走 pull/triage，预算上限机制沿用，3 万积压不清
- 每期一条主线；表格中「搭车」性质条目工程量必须 ≤1 天
- 所有验收 = 计数指标 + 复利代理并读；任何一期的淘汰条件触发即停，不带病推进

## 4. 度量体系总表

| 指标 | 采集点 | 服务于 |
|---|---|---|
| 真实调用数 / 跨天数 | mcp_call_logs | Phase 0 裁决（原 V0 条件） |
| 链路完成率（query→read_entry→get_source） | P0.1 分析脚本 | Phase 0 裁决并读、Phase 3 注入前置 |
| 检索 Top-3 命中率（20 条基线重放） | P0.2 基线 + Phase 2 重放 | Phase 2 验收 |
| 注入跟随率 / 会话引用证据 | mcp_call_logs + 人工抽查 | Phase 3 验收 |
| 写回会话知识引用率 | session_notes × 注入/查询记录关联 | **北极星**（Phase 4 起） |
| 日报打开数 | read_history(source=daily) | Phase 1 验收、Phase 4 渠道决策 |
