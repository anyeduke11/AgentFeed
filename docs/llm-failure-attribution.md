## 3. 失败形态推断（待 ① 根因复现确认）

错误存在两代格式（结构化 `{"kind":"internal",...}` 10,678 条 vs 裸串 7,847 条）说明重试链路也在演进，但**重试后依然 parse 不出的比率异常高**——指向系统性冲突而非偶发抽风。最可能的形态（按嫌疑排序）：

1. **callLlm 强制 `response_format=json_object` 与部分模型/组合不兼容**（静默不生效，模型仍输出对话式包裹）
2. 输出被围栏包裹/前后缀污染（JSON 提取只有各处手写兜底，无统一提取器）
3. max_tokens 截断产生残缺 JSON（I1 截断信封泄漏已实证此形态存在）

## 4. 裁决落地（2026-09-22 讨论定案）

| 项 | 处置 |
|---|---|
| **H1 输出契约** | **升格 v0.2.x 首批主体**：①根因复现（取 20 条失败样本原始输出确认形态，0.5 天）②callLlm 层统一修复——统一 JSON 提取器（围栏剥离/首对象提取，推广 I1 extractAnswer 经验）或 rawText 模式参数（对话场景解除 json_object 强制），0.5~1 天 ③治愈观测：失败率 27%→<5% |
| **H3 降级显式化** | **并入 H1①**：失败形态成文即降级文档（唯一真实降级场景=parse 重试耗尽，修好 H1 自然消失大半），不再单独立项 |
| H2 Prompt 一等公民 | 做，薄形态（`src/prompts/` 集中 + 每处标注"改后必跑 eval"），G3 前置已满足 |

## 5. 治愈观测口径（v0.2.x H1 验收）
