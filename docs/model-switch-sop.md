# G3 模型切换 SOP + AI 化判据

> 来源：v0.1.5 PRD 3.3.11 K1（G3 增补「模型切换 SOP」一节 + 2026-09-21 五次裁决「AI 化判据」成文，PRD v2.5）。
> 一句话价值主张：**模型是耗材、脚手架是资产——升级成本被 eval + 契约压到一次 config 切换，收益被四层资产自动放大。**

## 1. 换模型必跑清单（SOP）

适用场景：切换默认 LLM 服务商/模型（`ai.defaultProvider` / `ai.defaultModel`）、升级 provider 版本、改蒸馏 prompt 后想验证「质量没变差」。顺序执行，任何一步不达标即停，不切。

| 步骤 | 命令 / 操作 | 通过判据 |
|---|---|---|
| ① 质量评测（golden set） | 仓库根：`npx tsx server/scripts/qualityEval.ts`（可加 `--fail-below <rate>`，缺省 1.0） | exit 0——gate 一致率 ≥ 阈值；distill 覆盖率只报告不判退出，但需**不低于现基线数字**（新基线首跑记录在案后方可作为下限） |
| ② 语料锚点校验 | `server/` 目录：`npm run baseline:check` | exit 0 = 语料一致，检索基线有效；exit 1 = 语料已漂移（与换模型无关，先重跑 searchBaseline 更新基线再回来）；exit 2 = 基线文档缺指纹锚点（旧版，重跑生成） |
| ③ 画像蒸馏抽检 | 看板 Settings→用户画像→立即蒸馏（触发 `triggerProfileDistill`），人工审断言 | 断言可从统计推出、evidence 指针真实、无幻觉断言；vetoed 断言未被翻案、user_added 原样保留 |
| ④ 切换默认模型 | 全部持平或更好 → `PATCH /api/config`：`ai.defaultProvider` / `ai.defaultModel` | config 落库，后续蒸馏/画像/嵌入走新模型 |
| ⑤ 契约校验兜底 | 无需手动操作 | 见下 |

**⑤ 契约校验兜底说明**：即使评测遗漏，schema 拒收 fail loud 已内建——坏产物整包丢弃保留旧版，绝不半写：

- `safeParseWikiJson`（`server/src/llm/llmWorker.ts`）：蒸馏 JSON 不合法即失败重试，不落残缺词条；
- `parseProfileContent`（`server/src/profile/model.ts`）：画像 content 任何字段不合法整包拒收（返回 null 保留旧版）；
- `parseLlmProfileOutput`（`server/src/profile/distill.ts`）：LLM 引用了证据桶外的编号 = 幻觉指针，整包拒收抛 `invalid_llm_output`。

换模型后首日观察：G1 成本视图（`ai.pricing` 配价后）看新模型单价与用量；llm_call_logs 失败率；若配置了 `userProfile.syncTargets`，画像区块会随蒸馏成功自动同步（幂等，区块外字节不动）。

## 2. AI 化判据（PRD v2.5 裁决成文）

> 原则总纲：**判断可 AI、执行必代码、契约护栏拒收。** AI 只进「判断槽」，产物一律过确定性契约才能落状态。

### 2.1 三问测试

新功能/新改动要不要用模型，依次问：

1. **有固定答案吗？**——可枚举、可计算的（路径校验、排序数值、配额计数、格式转换）必代码。模型答固定答案题是引入一个会出错的查表。
2. **错误代价在展示层还是状态层？**——错误只影响一次展示（可刷新可忽略）可放宽；要写入状态（DB/文件/配置）则**判断可以 AI、执行必须代码**，且写入口过契约校验。
3. **输出可校验可否决吗？**——不能校验的输出（无法定义对错、无法对照真值）不进状态层；可校验（schema/指纹/回放）才允许模型产物落库，并保留否决通道（如画像 vetoed）。

三问有任一答「固定答案」或「不可校验进状态层」，判代码。

### 2.2 灰区裁决表（已裁决案例，后续同类对齐）

| 场景 | 裁决 | 理由 |
|---|---|---|
| I3 推送**时机**（此刻是否值得打扰用户） | **模型判断**，但打扰控制由代码硬顶：每日 ≤1 次、可全局关 | 时机判断无固定答案、错误代价在打扰层（低）；频率与开关是可计算约束，必代码 |
| I3 推送**内容**（学什么、怎么表述） | **AI 生成** + 长度护栏 | 内容生成是模型所长；护栏（长度上限）是确定性约束 |
| E1 归因分类（断链四分类） | **确定性启发式**（词面重合 CJK 二元组 ≥0.2 初筛 + 重放） | 分类可枚举、判定可重放，固定答案题 |
| 对话改配置 / 写库 | **永远禁止** | 状态层写入，错误代价不可逆；配置变更必须人点按钮/显式 API |
| 画像断言生成（J1） | **AI 判断 + 契约拒收 + 用户可否决** | 三问全过：无固定答案、写状态层但整包 schema 校验、vetoed 即否决 |
| D2 排序回流权重 | **纯代码**（本地聚合计算，LLM 零参与） | 数值可计算必代码；见 `docs/feedback-loop-design.md` 第 3 节 |

### 2.3 确定性内核清单（模型零接触）

以下六项是系统安全与可复现的承重墙，**模型永远不参与，改动必须测试钉死**：

| 内核 | 现状锚点 | 钉死测试 |
|---|---|---|
| 扫描根边界 | 任何读磁盘端点必过 `withinScanRoots`（files.ts 模式） | 越界路径返回拒绝 |
| reader 白名单 | 服务端 cheerio 清洗 + iframe sandbox 无 allow-scripts 双保险 | `reader.test.ts` 6 安全用例（script/on*/危险协议/危险标签） |
| `ensureColumns` 迁移 | 只幂等加列（PRAGMA 检查后 ALTER ADD），不写破坏性迁移 | 迁移链幂等重跑 |
| 队列调度 / 预算闸 / 熔断 | `llmQueue` 优先级、`budgetGate.enforceDailyBudget`（日预算）、provider 熔断 | 预算超限拒发、恢复窗口 |
| 评分与排序先验 | `quality_score×3 + rule_score` 双轨（getContext/推荐池口径）；D2 回流为加法项 | 先验公式可复现 |
| 幂等协议 + API 契约 | 画像托管区块幂等（区块外字节不变）、`{ success: boolean }` 响应约定 | 重写 N 次字节不变；契约用例 |

## 3. 脚手架五原则

模型是耗材、脚手架是资产——四层资产（上下文工程/记忆资产/工具生态/数据飞轮）单调增值，模型巧思快速折旧。五原则是资产的维护纪律：

1. **契约优先**：模型输出先定义 schema 再写 prompt，坏产物整包拒收——例证：画像蒸馏「LLM 只产 active 断言 + evidence 引用编号，本地翻译回指针，非法引用整包拒收」。
2. **确定性内核 + 模型边缘**：判断放模型、执行放代码（第 2.3 节清单模型零接触）——例证：门禁判定是纯规则（gate.ts），蒸馏才是 LLM；预算闸在任何 LLM 调用之前。
3. **评测是免疫系统**：没有 golden set 与基线对照，「质量没变差」只是感觉——例证：`qualityEval.ts` 负向验证成立（改坏 prompt → 一致率下降 → exit 1），`baseline:check` 三态锚点让语料漂移机械可检。
4. **禁止模型特调**：不为某个模型版本写分支逻辑或专属 prompt 补丁——模型会换，特调代码会烂在库里；发现模型短板先改契约/评测，再考虑换模型（走第 1 节 SOP）。
5. **版本一切**：凡是会演化的产物（画像 content、导出 manifest、语料基线）都带版本与指纹——例证：`user_profile` 版本链可回滚，`exportWiki.ts` SHA-256 指纹让 recompile 前后可机械 diff（三门激活口径见 `docs/feedback-loop-design.md` 第 2 节）。
