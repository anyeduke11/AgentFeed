## 评审标记

**状态：已评审——产品与度量视野最完整但答错题目；六处真增量收编，约四成机制因产品错位否决。**

### 判定核心：产品错位

千问把 AgentFeed 当成多用户 RSS/资讯消费 SaaS 设计，而真实形态是**单用户本地库、零推送、纯拉取**：

| 千问假设 | AgentFeed 现实 |
|---|---|
| attention_quota.user_id、多用户画像/权重向量 | 单用户本地 SQLite，无账户体系 |
| 「推送即打断」→ 模块 C 整层（静默窗口/批次推送/interrupt_count） | 零推送面：Web + MCP 全拉取式，不存在「被打断」 |
| 跨源事件聚合 + 分歧点（side_a/side_b/sources） | 语料是 Agent 工作产物，非新闻事件 |
| DAU、NPS、推送打开率、团队 KPI 考核叙事 | 个人本地工具 |
| 0-6/6-16/16+ 周交付周期（P0 任务 40+ 人日） | 月级体量对单机改造严重超配 |

### 六处真增量（前三份均无，已收编进 v1.4）

1. `total_available_but_hidden` 内联可见——feed 响应自带「还有 N 条被拦下」，对 FOMO 心理最精准（→ P3-1）
2. 软/硬双上限渐进降级（80% soft 只许 L1 / 100% hard 停止，降级不惩罚）（→ P3-1）
3. digest/周报不占当日预算——激励聚合替代实时流（→ P3-1）
4. 两指标：dedup_compression_ratio（2.5-6× 健康区间，→ P1-5）；budget_used_pct（60-85% 健康，→ P3）
5. 动态阈值 p70（消费越少阈值越高）——P3+ 备选，不设默认
6. 反馈权重更新规则（dismiss_forever ×0.3 / false_alarm 回退重审 20 条 / save+dwell 正样本 ≤5% 步长）——backlog（≥50 条信号后评估）

### 否决清单

- 模块 C 整层（delivery windows / quiet / 批次推送 / interrupt_count）：产品错位，无推送面
- emergency 追加预算：与已采纳的智谱「改配置次日生效」冲突，取更严者
- 反馈模块 F 全家（8 action + dwell_ms 埋点 + 权重引擎）：架在零信号基线上（12 天 1 条打分），dwell 埋点不存在
- API 信封 `{code,msg,data,trace_id}`：违反仓库红线 4（`{ success }` 约定）；语义状态码取值保留
- cluster 分歧点语义：新闻语法不适用 Agent 产物语料
- 源权重/衰减/末位标红：方向有趣（映射到 scan root 维度才有意义），记 backlog
- 拦截率 ≥70% 验收：与元宝 95% 同病，天然满足的虚荣指标

### 任务清单文件处置

格式最专业（任务编号/工时/依赖/逐任务验收），但拆的是错位产品的题——不并入排期。两条借用：①其 P0 40+ 人日作为「此类方案体量月级」的实证锚点；②逐任务验收格式纪律（v1.3 §6 已具备）。
